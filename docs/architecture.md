运行栈是 Vue 3、Vite、Vant、ECharts 和 Axios；后端是 Node.js 22+、Express 5、mysql2；可选 Python 环境包括 Garmin Connect/curl_cffi，以及 joblib、NumPy、scikit-learn 和 mysql-connector-python。依赖版本由各自 lockfile 和 requirements 管理。

## 数据流与权限

Garmin 下载端输出 FIT 和健康 JSON，Python 转换为结构化 SQL，后端按配置数据库执行并记录同步状态。活动距离以米、时长以秒，UTC 时间与设备本地开始时间分字段存储。运动列表、详情和统计按所属用户筛选；管理员在管理视图保留显式跨用户查询。健康查询使用登录用户的 ID。教练可从同一套数据获得训练与恢复摘要，配置 DeepSeek 密钥后，提示词中会带上近期摘要，启用云端前应明确展示处理范围。

已识别的后续工作：

- Garmin 首次同步查询最近 28 天。活动入库时写入账号归属，以账号与 Garmin ID 或 FIT 指纹查重。旧记录保留原归属。
- 现有 AI/表现画像带有无归属旧记录的兼容分支。新计划和训练上下文查询要绑定显式用户 ID，移除对这些兼容分支的依赖。
- 保留原有单次跑步模型接口，未配置模型时报告不可用；现有日常建议和表现评分可使用规则。下一阶段需显式区分缺失数据、真实零值和演示数据。

## 阶段 1 数据模型与迁移

首个增量迁移增加 `TrainingPlans` 与 `TrainingSessions`。计划保存用户、运动类别、目标模板、目标说明、本地起始日期、周数和阶段、状态与版本。任务按本地日期存储类别、距离、时长和执行状态。周历从起始日期展开，并由任务日期推导可训练日和周频率。计划按用户与状态索引，任务按计划与日期建立唯一索引，同一计划的一天最多一项任务。

计划更新锁定所属用户的计划记录，在事务内检查版本并写入任务。活动计划使用带唯一索引的虚拟列约束，并发激活时只允许一个成功。已完成和跳过的任务保留原有安排。归档计划只读。训练上下文沿用活动查询的用户过滤、统计计算和健康汇总表，以 `Asia/Shanghai` 日期生成 7/28 天窗口，返回样本覆盖、合成记录标识和缺失值。

增量 SQL 可重复执行，现有阶段 0 开发库无需重建。旧版课表由浏览器全局键保存，阶段 1 保留原键内容并停用读取，避免旧记录被分配给当前登录的其他账号。会话、审批动作、活动匹配和修订表按后续阶段引入。

## 阶段 2 教练与确认流程

计划助手和日常问答并列在教练页。计划助手调用 `get_training_context` 与 `get_active_plan`。规则生成器只生成四周轻松跑、跑走或恢复课表，并在每次生成及确认时使用已有的 `readPlan` 校验。相邻训练日中的后一日会缩短并降低强度。无有效历史时显示基础模板，近期缺少睡眠及 HRV 依据时保持初始训练量。

默认由本地规则识别目标。可选的 DeepSeek 路径只发送用户本轮输入，最多发起一次限时 JSON 请求。服务端验证分类、训练日、频率和工具名，再以鉴权账号执行读取。工具不接受模型提供的账号 ID，也不接收模型生成的 SQL、URL 或写入动作。模型超时、输出无效或工具越权时使用本地规则。配置说明见 [README](../README.md#使用教练计划助手)。

| 表 | 用途 |
| --- | --- |
| `AgentConversations` | 会话与归属 |
| `AgentMessages` | 保存每轮消息、数据依据和工具状态，按会话、客户端消息 ID 与角色去重 |
| `AgentActions` | 保存草案、有效期、处理状态和结果计划 ID |

外部模型调用在写入事务外执行。本轮消息和审批动作在一个事务保存。确认时锁定审批动作，复查归属、有效期、训练字段和当前状态，再在同一事务内保存计划、任务及结果 ID。重复确认重放已有结果。已有活动计划时可另存为草稿，也可能因确认前出现竞争计划而得到明确失败状态。

## 阶段 3 导入、执行反馈与计划修订

网页 FIT 导入与 Garmin 同步共用 Python FIT 转换与入库流程。同一批活动在事务中提交，重复项逐条回滚到保存点，导入完成后才检查自动匹配。同账号、同日、同为跑步且候选唯一时，还须满足目标量偏差阈值才自动关联。手动关联在任务日前后 7 天范围内选取，归属、计划版本、任务状态和一对一约束由服务端复查。

`TrainingSessionActivities` 存储关联时的计划/实际快照，保持已完成任务的原始依据。手动编辑原活动或删除原记录后，历史快照仍可查看。训练计划版本随确认修订、状态变化或活动关联增加。`PlanRevisions` 保存已启用课表的实际编辑和确认修订，可解释每次改期或减量。

本地教练规则优先处理执行回顾、同训练周内改期及单次减量。调整草案包含任务 ID、原计划版本、前后数据和理由。审批与计划更新在同一事务执行，确认冲突不会覆盖新版本。用户描述恢复偏弱时，结合已有恢复记录给出简短依据，缺少记录时把该限制显式展示。

### 下周训练建议

`weekly-guidance-v1` 复用训练上下文和执行中计划。规则要求近 7 天有可用跑步时长，近 28 天至少有 3 条跑步记录。下周有待训练任务时，本周至少有两项到期且存在未完成项，可以提出一次约 15% 的减量。近 7 天有至少两条同类睡眠观测且平均时长低于 6 小时或平均评分低于 60 时，也可触发减量建议。这些阈值用于生成保守的训练候选。HRV 提供覆盖情况。

教练收到周报预览请求后重新计算建议。确认沿用原有审批事务，检查当前周、计划版本、账号归属和任务状态。一份计划每周只能应用一次周报建议，修订历史保存实际改动。

后端 184 项测试、前端 108 项检查和生产构建均通过。隔离 MySQL 与 Chrome 360px 验证了数据不足、维持、减量前后对比、拒绝、确认、旧版本冲突、跨账号拒绝和确认后回读修订记录。

### Agent 增强顺序

1. **主动澄清是优先增量。** 复用会话消息和结构化卡保存当轮缺失项。收集目标、可训练日、开始日和时长上限，最多追问两个关键问题，提供取消和明确选择默认值。用户只补充「周三和周日」时，下一轮应接上之前的目标。评审已复现当前独立处理每轮导致重复追问，验收应覆盖刷新、取消、过期和跨账号。晨间状态可在用户需要调整时按自评读取并标明来源。
2. **先站内提醒，再后台投递。** 首页显示待训练和可回顾周报。用户开启定时提醒后，复用单一系统调度和 MySQL 通知记录，用账号、提醒类型和时间周期去重。验收准则是重复触发只出现一次、重启可有限补跑、归档或关闭后不继续提示。系统推送等出现明确需求时再接入。
3. **近期赛事先做只读汇总。** 从一个地区、未来 90 天和少量官方条目起步，标识赛期、距离、报名状态、来源与最后核对时间。年度赛历用来查候选，当届公告核对日期和状态。稳定数据源和使用许可明确后再自动更新。跑者主动选择赛事时可以生成支持目标范围内的计划草案。[中国田协年度赛历信息](https://www.sport.gov.cn/n14471/n14495/n14543/c29312946/content.html) [官方 5/10 公里活动示例](https://www.sport.gov.cn/stzx/n5434/c30107235/content.html)。

为消除历史双轨技术债并补齐空间轨迹与赛事数据闭环，本轮完成了以下工程治理与功能升级：

1. **移除遗留双轨 Agent 与 Python ML 依赖**：
   - 删除 8 个旧版 Agent 调度/查询文件（`coachAgent.js`、`coachActivityAgent.js`、`coachAnalysisAgent.js`、`coachToolLoop.js`、`coachActivityQuery.js`、`coachPerformanceEvidence.js`、`coachPerformanceScope.js`、`coachPlanWorkflow.js`）及 7 个旧评估脚本，统一收敛至 `coachHarness.js` + `coachTelemetryService.js` 单一架构。
   - 移除 `backend/ml/` Python 训练/推理脚本、`mlRoutes.js` 与 `coachMlService.js`，以纯 JS `trainingReadinessService.js` 支撑 `performanceProfileService.js`（路由迁移至 `GET /api/training/performance-profile`）及日常简报规则基线，后端测试不再依赖本地 Python ML 环境。
   - 清理前端无引用死文件 `Assistant.vue`、`runningEvents.js` 及 `predictRunningLoad`。
2. **国内半马/全马自动爬虫与 MySQL 目标赛事闭环（迁移 12–13）**：
   - `marathonEventCrawlerService.js` 定时每 12 小时自动抓取 `chinamarathon.com`，严格过滤并仅入库国内半程与全程马拉松（`MarathonEvents` 表），解析失败时保留缓存并记录 `lastCrawlError`。
   - 新增 `UserMarathonEvents` 表及 `/api/explore/my-events` CRUD，取代原浏览器 `localStorage` 收藏，并将用户目标赛事与倒计时自动注入 `coachHarness.js` 系统提示词与 `get_upcoming_marathon_events` 工具上下文。
   - 前端新增 `UpcomingMarathonWidget.vue` 挂载至 AI 教练欢迎页与「今日」主页，支持 `全部 / 全马 / 半马` 切换与一键「AI 备赛」。
3. **高德地图 JS API 2.0 与免 Key 离线轨迹降级**：
   - `RoutePreview.vue` 支持高德 Web 端 JS API 2.0 真实底图（含 WGS-84 → GCJ-02 纠偏、配速渐变轨迹、起终点与公里标点），同时支持生产 Nginx `AMAP_SERVICE_HOST` 代理模式以隐藏 `securityCode`；在未配置 Key 或离线场景下自动降级渲染深色高精度 SVG 配速轨迹图。
