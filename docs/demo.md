# 执行反馈闭环演示

使用本地 SpAgent、已完成的数据库迁移以及一个全新的演示账号。使用 [启动步骤](../README.md#本地启动) 后在网页注册。

## 准备合成 FIT

使用 Garmin 官方 SDK 生成一条 3000 米、18 分钟的跑步。文件只含模拟记录，生成默认使用北京时间当天。Python 环境中的 SDK 仅用于生成演示文件，程序导入仍复用仓库内的现有解析器。 [Garmin FIT Python SDK](https://github.com/garmin/fit-python-sdk)

```powershell
python -m pip install garmin-fit-sdk==21.222.0
python database/scripts/create_demo_fit.py
```

文件位于 `database/data/fit/synthetic-demo.fit`。

## 页面演示

1. 在「教练 → 计划助手」提出四周目标，明确以当天开始，并安排今天及明天对应的每周训练日。例如当天是 2026-11-19 周四，可输入「我想为首次 5 公里做准备，从 2026-11-19 开始，每周四、五有空」。确认并启用草案。
2. 从「我的 → 同步」上传刚生成的 FIT，确认导入，打开运动详情的「分析」。对应当天的待训练任务可自动关联。若存在多条同日跑步或目标偏差过大，从「训练任务复盘」选择任务并确认关联。
3. 在运动详情或「训练计划」查看计划与实际差异。基础模板的第一次安排通常为 15 分钟，示例 FIT 的实际时长多 3 分钟，距离和配速差值按计划是否提供目标显示。重复上传同一文件可看到去重提示。
4. 回到教练，输入「把明天的训练移到后天」。查看变更前后，先拒绝并核对周历，重新提出相同调整，再确认。或者输入「下一次训练减量 20%」验证单次减量。
5. 打开更新后的计划，展开「修订历史」。刷新并重新进入历史，核对版本号和原因，以及已完成的首个任务仍保留复盘。换一个账号登录后，核对计划及会话相互隔离。

全部操作可使用合成数据和本地规则完成。切换到新的本地账号可重复演示。
